# Critical user flows

This is a single-page portfolio. The route registry currently contains `/`; anchors, the project gallery, and the contact form are the interactive flows.

| ID    | User task (non-leading)                                                                                           | Success criteria                                                                                                                                                                      | Failure definition                                                                                            | Metrics / budget                                                                                        |
| ----- | ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| UF-01 | You want to understand Mihir's experience and selected work before contacting him; find the relevant information. | A visitor can reach Experience, Projects, and Contact through desktop navigation or the mobile menu, and each target is visible below the fixed header.                               | A destination is unreachable, obscured, loops, or the mobile menu cannot be closed.                           | Completion 100%; 0 navigation errors; <= 3 clicks; <= 20 seconds.                                       |
| UF-02 | You have an enquiry and need to start an email with your contact details and project scope.                       | Required fields reject empty/invalid entries; valid Unicode/long text is retained; the app clearly tells the user it opened their email client rather than claiming to transmit data. | Invalid data is accepted, submission can happen twice, input is lost, or the UI falsely reports transmission. | Completion 100%; 0 validation errors after correction; <= 4 actions after reaching form; <= 45 seconds. |
| UF-03 | You need to compare the listed projects without losing your place.                                                | Gallery slide controls show one active slide, are keyboard/touch reachable, and the page recovers after Back/Forward.                                                                 | More than one/no slide is active, controls are too small, or history leaves a blank/broken page.              | Completion 100%; 0 errors; <= 2 interactions to compare; <= 15 seconds.                                 |

Automated checks simulate these tasks at the configured projects. They are not evidence of real-user comprehension or trust.
